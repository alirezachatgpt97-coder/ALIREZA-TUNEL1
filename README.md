# ALIREZATUNEL

رابط و رنگ و فونت کاریز، مدیریت سرورها و تونل با موتور واقعی BackPack.

## آماده‌سازی گیت‌هاب، یک بار

ZIP اصلی را استخراج کنید. فایل‌های داخلش را در ریشهٔ این مخزن آپلود کنید:

https://github.com/alirezachatgpt97-coder/ALIREZA-TUNEL1

ZIP اصلی را روی ویندوز Extract All کنید. داخل پوشهٔ استخراج‌شده بروید و با Ctrl+A تمام فایل‌ها **و پوشهٔ `.github`** را انتخاب کنید. در گیت‌هاب Add file → Upload files را باز کنید و همهٔ موارد انتخاب‌شده را با ماوس داخل صفحه بکشید؛ سپس Commit changes را بزنید.

از دکمهٔ انتخاب فایل برای آپلود پوشه استفاده نکنید؛ پوشهٔ `.github` هم باید همراه فایل‌ها Drag & Drop شود. خود ZIP اصلی را در مخزن آپلود نکنید و ZIP داخلی `ALIREZATUNEL-SOURCE.zip` را هم استخراج نکنید.

پس از آپلود باید در صفحهٔ اصلی مخزن پوشهٔ `.github` را ببینید و داخلش مسیر `workflows/build.yml` موجود باشد. ساخت دستی هیچ فایل لازم نیست. باقی فایل‌های ریشه: `ALIREZATUNEL-SOURCE.zip`، `SOURCE.sha256`، `bootstrap.sh`، `install.sh`، `README.md`، `BUILD-NOTES.md` و `SHA256SUMS`.

پس از آپلود، در **Actions → Build ALIREZATUNEL** ساخت خودکار شروع می‌شود. اگر Actions غیرفعال بود، آن را فعال و Run workflow را بزنید. صبر کنید هر دو معماری و مرحلهٔ Publish سبز شوند؛ باینری‌های تازه در Releases قرار می‌گیرند. این مرحله فقط روی گیت‌هاب انجام می‌شود؛ نصب VPS هیچ Rust یا Go کامپایل نمی‌کند.

این بسته شامل سورس اصلاح‌شده و ابزار ساخت است. باینری‌های نسخهٔ جدید هنوز در این محیط ساخته نشده‌اند. فایل‌های اجرایی ۵۴ مگابایتی قبلی را نسخهٔ جدید حساب نکنید. نصب‌کننده اگر آخرین Release با سورس جدید تطابق نداشته باشد، نصب نسخهٔ قدیمی را متوقف می‌کند.

## نصب یا ارتقای پنل

روی Debian 12/13 یا Ubuntu 22.04/24.04 دارای systemd با root و داخل SSH تعاملی:

```bash
curl -fL --retry 3 https://raw.githubusercontent.com/alirezachatgpt97-coder/ALIREZA-TUNEL1/main/bootstrap.sh -o /root/install.sh && bash /root/install.sh panel
```

نصب می‌پرسد:

1. SSL برای دامنه، IP عمومی، یا گواهی معتبر موجود؟
2. دامنه/IP و ایمیل ACME؛ پذیرش شرایط CA؛ روش standalone یا مسیر webroot.
3. پورت HTTPS (پیشنهاد 443) و پورت پایهٔ ایجنت (پیشنهاد 29001).
4. پسورد انتخابی و تأیید آن، حداقل ۱۲ کاراکتر.

SSL معتبر الزامی است. خطای صدور یا زنجیره/نام/کلید اشتباه باعث توقف تنظیمات می‌شود. هیچ self-signed به عنوان نصب موفق معرفی نمی‌شود. پس از رفع مشکل: `tun configure`.

برای صدور و تمدید HTTP-01، TCP 80 باید از اینترنت باز باشد؛ دامنه باید به همان سرور اشاره کند. نصب‌کننده وب‌سرور دیگر را متوقف نمی‌کند؛ اگر 80 اشغال است webroot انتخاب کنید. SSL عمومی IP با Certbot 5.4+ و پروفایل shortlived گرفته می‌شود. تمدید خودکار دو بار در روز بررسی می‌شود و reload با اعتبارسنجی انجام می‌شود. گواهی سفارشی را از مسیر ارائه‌دهندهٔ خودش تمدید و سپس `tun reload-tls` اجرا کنید.

اگر UFW فعال باشد، قوانین HTTPS، HTTP challenge و پورت‌های مدیریتی افزوده می‌شوند. فایروال شرکت میزبان را باید در پنل همان شرکت باز کنید.

## سرورها و ایجنت

از بخش سرورها، Add server را بزنید و IP/دامنهٔ قابل‌دسترسی پنل را وارد کنید. فرمان تولیدشده را با root روی سرور جدید اجرا کنید: ابتدا بستهٔ آماده نصب می‌شود، سپس کد اتصال اعمال می‌شود. اسکریپت تا ۹۰ ثانیه منتظر هویت تأییدشدهٔ پنل می‌ماند و صرفاً به دلیل روشن بودن سرویس، موفقیت اعلام نمی‌کند.

روی پنل، پورت پایهٔ ایجنت و پورت بعدی آن باید برای TCP و UDP باز باشند؛ مقدار واقعی را هنگام افزودن سرور ببینید. حالت reverse، همین پورت‌ها را روی سمت عامل نیاز دارد. `tun agent-test` و `tun logs` خطاهای اتصال را نشان می‌دهند. کد منقضی‌شده، IP اشتباه، ساعت نادرست و فایروال بیرونی از علت‌های رایج‌اند.

نصب دستی عامل:

```bash
bash /root/install.sh agent
alirezatunel-join JOIN_CODE
```

ارتقای عامل ثبت‌شده با `tun update` هویت را حفظ می‌کند؛ برای ارتقا دوباره Join نزنید. هر عامل را جداگانه ارتقا دهید؛ پنل جدید به‌تنهایی عامل قدیمی را عوض نمی‌کند.

## تونل‌ها و پورت فوروارد

تونل جدید فقط BackPack است. روش‌های reverse شامل TCP، TCP Mux، Stealth، PCK، UDP، KCP/FEC، QUIC، WS، WS Mux، WSS، WSS Mux و xDi هستند. حالت مستقیم از حامل‌های لایهٔ ۳ خود BackPack استفاده می‌کند. پروتکل‌های GRE کاریز در منو یا ساخت تونل عرضه نمی‌شوند. کتابخانهٔ کاریز برای ارتباط مدیریتی داخلی پنل/عامل باقی است؛ ترافیک تونل با باینری مستقل BackPack منتقل می‌شود.

ابتدا دو سرور و تونل را بسازید؛ امکان ساخت تونل بدون پورت عمومی وجود دارد. سپس در «پورت فوروارد»، تونل موجود را انتخاب و ورودی و مقصد را اضافه کنید:

```text
0.0.0.0:443        → 127.0.0.1:443
0.0.0.0:8000-8009  → 127.0.0.1:9000-9009
0.0.0.0:8080       → host1:80|host2:80
```

پروتکل همهٔ نگاشت‌ها TCP یا TCP+UDP است؛ حامل خام UDP فقط UDP دارد. حداکثر ۲۰۰ قانون، ۱۰۲۴ پورت در هر بازه و مجموع ۴۰۹۵ پورت پشتیبانی می‌شود. pool مقصد تا ۱۶ آدرس و فقط برای پورت تکی است. ذخیرهٔ تغییرات، هر دو طرف تونل را ریستارت می‌کند و پنل عملیات و خطا/بازگردانی را نشان می‌دهد.

## تست سرعت و مدیریت تونل

صفحهٔ هر تونل آمار زندهٔ موتور، اتصال و ظرفیت pool، KCP، منابع و وضعیت مقصد را وقتی موتور گزارش بدهد نشان می‌دهد. تست سرعت از یک نگاشت خصوصی داخل **همان تونل BackPack** عبور می‌کند؛ ارتباط مدیریتی فقط تست را هماهنگ می‌کند. سنجش دانلود، آپلود، تأخیر بیکار و زیر بار، jitter و اتلاف UDP موجود است. برای UDP-only دو عدد سرعت، goodput یک echo هستند و ظرفیت مستقل هر جهت نیستند؛ این موضوع در گزارش نوشته می‌شود. Peak در این ابزار میانگین مرحله است، نه قلهٔ لحظه‌ای اندازه‌گیری‌شده.

پورت‌های خصوصی اندازه‌گیری از محدودهٔ 15000–17999 و 25000–27999 برای هر نام تونل تعیین می‌شوند و قانون عمومی هم‌پوشان رد می‌شود. ابزار با توکن تصادفی، فقط هنگام تست و حداکثر ۱۸۰ ثانیه اجرا می‌شود؛ پایان یا توقف تست، درخواست پاک‌سازی می‌فرستد. اگر تست قطع شد و بلافاصله پورت مشغول بود، تا پایان مهلت پاک‌سازی صبر کنید.

برای تونل قدیمی پس از ارتقای **هر دو عامل**، یک بار پورت فوروارد را ذخیره کنید تا نگاشت خصوصی تست هم اضافه شود. این کار تونل را ریستارت می‌کند.

حامل‌های raw-IP/PCK/ICMP/Spoof و لایهٔ ۳ به مجوزها و امکانات کرنل و شبکهٔ میزبان نیاز دارند. پشتیبانی کد به معنای امکان عبور همهٔ این بسته‌ها از هر شرکت میزبان نیست.

## منوی ترمینال

```bash
tun
```

گزینه‌ها: آدرس ثابت پنل، مشاهدهٔ پسورد، تعویض/ریست پسورد، تنظیم و بررسی/تمدید SSL، وضعیت سرویس‌ها، لاگ‌ها، restart، reload TLS، عیب‌یابی عامل، بکاپ، update و configure.

پسورد ورود در دیتابیس Argon2 است. برای قابلیت مشاهدهٔ پسورد که خواسته‌اید، یک نسخهٔ قابل‌خواندن فقط توسط root، در پوشهٔ 0700 و فایل 0600 ذخیره می‌شود. اگر از وب عوضش کنید، نسخهٔ قدیمی نمایش داده نمی‌شود و `tun password` برای ساخت نسخهٔ جدید پیشنهاد می‌شود. بکاپ شامل اطلاعات حساس است و با مجوز 0600 در `/root` ساخته می‌شود. رابط جدید لینک موقت ورود ارائه نمی‌کند؛ آدرس ثابت همراه پسورد استفاده می‌شود.

دامنهٔ بررسی‌ها و محدودیت‌های واقعی ساخت در `BUILD-NOTES.md` نوشته شده است.
